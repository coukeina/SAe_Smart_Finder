# Sprint 04 — Documentation client (Semaines 11 à 12)

## Objectifs du Sprint
- Rédiger la documentation côté client : un guide utilisateur pour une personne non technique (`docs/guide_utilisateur.md`).
- Couvrir tout le parcours de l'application : photo, analyse, correction des ingrédients, préférences, recettes, inventaire.
- Aider l'utilisateur à se dépanner seul grâce à une FAQ construite sur les vrais messages de l'application.

## Backlog

- **DC01** : Cadrer le guide (public cible, parcours à documenter, format Markdown avec export PDF possible).
- **DC02** : Rédiger le guide de démarrage (lancer l'application, ouvrir `http://localhost:7860`).
- **DC03** : Rédiger le parcours pas à pas : photo → analyse → correction → préférences → recettes → inventaire.
- **DC04** : Ajouter les captures d'écran annotées de chaque étape.
- **DC05** : Rédiger les conseils pour réussir sa photo.
- **DC06** : Rédiger la FAQ et le dépannage à partir des messages d'erreur de l'application.
- **DC07** : Ajouter le glossaire (vocabulaire simple, sans jargon technique).
- **DC08** : Faire relire et tester le guide par une personne qui ne connaît pas l'application, puis corriger.
- **DC09** : Intégrer le guide au dépôt (`docs/`) et ajouter le lien depuis le `README.md`.

## Définition of Ready (DoR)
- Sprints 01 à 03 terminés : application fonctionnelle et interface stabilisée, pour que les captures restent valables.
- Application lançable en local avec les 3 services Docker.
- Libellés exacts de l'interface relevés (boutons, champs, messages d'erreur).

## Définition of Done (DoD)
- `docs/guide_utilisateur.md` complet : démarrage, parcours pas à pas, conseils photo, FAQ, glossaire.
- Chaque étape illustrée par une capture d'écran annotée (`docs/img/`).
- Libellés du guide identiques à ceux de l'interface.
- Guide testé par une personne extérieure au projet, retours pris en compte.
- Lien vers le guide depuis le `README.md`.
